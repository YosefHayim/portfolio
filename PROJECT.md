# Project

## Register

personal portfolio / proof-of-work publishing system

## Users

Recruiters, hiring managers, technical leads, founders, collaborators, and Joseph Sabag as
the publisher.

## Project Purpose

This repo powers Joseph's personal portfolio website: a living place to spread thoughts,
work, project ideas, experiments, apps, and proof of technical growth. It should read as a
sharp proof-of-work journey, not a static resume or generic project grid.

Success means a recruiter can answer three questions in under a minute:

1. What kind of engineer is Joseph?
2. Why is his path unusual?
3. Which shipped work proves it?

For Joseph, success also means the site is easy to keep publishing into: posts, projects,
apps, experiments, assistant knowledge, and future ideas should all feel like parts of one
coherent system.

## Core Insight

The site itself is proof. A dense, evolving body of work is stronger than a resume template,
a detached blog, or a disconnected project list.

## Goals

- Make identity, edge, credibility, and contact obvious in the first minute.
- Let visitors browse projects, apps, writing, ideas, and version eras without losing the
  through-line.
- Give Joseph a stable publishing surface for thoughts, work, experiments, and future
  project ideas.
- Keep the Portfolio Assistant grounded in the same evidence as the visible site.
- Preserve the version showcase: clientV1, clientV2, and clientV3 are eras of one site.

## Non-goals

- Generic portfolio template.
- Detached lifestyle blog.
- SEO content farm.
- Resume wall where every project looks equally important.
- Separate deployments for version eras.
- Restyling frozen clientV1/clientV2 snapshots to match current style rules.

## Brand Personality

Precise, practical, restless, and direct. Confidence should come from shipped evidence, not
from self-promotion.

## Design Principles

1. Lead with the journey: show the progression from spotting manual work to shipping useful
   AI/full-stack systems.
2. Make evidence scannable: every claim should connect to a project, production result,
   post, experiment, or measurable outcome.
3. Prioritize recruiter speed: the first screen should answer identity, edge, credibility,
   and contact.
4. Preserve technical sharpness: use dense, clean structure without hiding behind decorative
   effects.
5. Show range through contrast: production work, mobile apps, extensions, automation tools,
   writing, and open-source systems should feel like one operating pattern.

## Accessibility & Inclusion

Target WCAG AA contrast, keyboard-reachable links and controls, reduced-motion support,
readable line lengths, localized recruiter-facing copy, RTL support, and responsive layouts
that keep recruiter-critical content visible on mobile.
